# Implemented foundation data dictionary

Generated by `npm run db:dictionary` from disposable embedded PostgreSQL catalogs after migrations, two seed passes and security assertions succeed. This documents implemented foundation SQL only; it does not certify Supabase HTTP or production behavior. Planned later-domain tables remain in [schema-inventory.md](schema-inventory.md).

Physical owner is the trusted migration role (shown below); business ownership and exposure come from subject FKs, grants and policies. Security-definer helpers run as this trusted owner, bypassing owner RLS to avoid recursion; FORCE RLS is deliberately absent. Never grant this role to users or ship service-role credentials.

All ON DELETE rules below are derived from actual constraints. Mutable rows use the `onit_updated_at` trigger. Historical records are retained with archival/status fields or immutable mutation guards; no general end-user DELETE is granted. Private tables have no browser policy or grants. The generic purpose for any unannotated table is its typed entity role described in the capability inventory.

Implemented base tables: **79**. Schemas: public and private; helper functions in app_private.
